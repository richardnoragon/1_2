## 1. Selection Methodology

### 1.1 Evaluation Criteria

| Criterion                | Weight | Description                          |
| ------------------------ | ------ | ------------------------------------ |
| **Business Criticality** | 30%    | Importance to core RFU functionality |
| **Coverage Gap**         | 25%    | Fills gaps in 859-test baseline      |
| **Modernization Effort** | 25%    | Lower effort = higher score          |
| **Code Quality**         | 20%    | Well-structured, reusable assertions |

### 1.2 Scoring System

-   **Score 10:** Critical functionality, simple import changes, high coverage impact
-   **Score 7-9:** Important functionality, moderate complexity
-   **Score 4-6:** Useful but not critical, some complexity
-   **Score 1-3:** Nice to have, high complexity or limited value

### 1.3 Exclusion Criteria

Tests are EXCLUDED from selection if:

-   Already have equivalent coverage in 859-test baseline
-   Reference functionality removed in architecture cleanup
-   Require unimplemented models (MISSING_MODEL_TEST_PATTERNS)
-   Are phase-specific development artifacts

-   **Business Value:** Essential for file operations workflow, frequently used feature
-   **Current Coverage:** Compression tests may exist but logic-level coverage missing

-   **Risk:** LOW - Uses standard library (zipfile, tarfile)
-   **Coverage Impact:** Fills gap in file operations testing

#### test_secure_delete.py (Rank #3)

-   **Business Value:** Security feature with enterprise compliance requirements
-   **Current Coverage:** HP-01 validated lockout, but secure deletion uncovered
-   **Modernization:** Medium - import path to src.tools.security.core
-   **Test Quality:** Tests secure overwriting, verification, error handling
-   **Risk:** MEDIUM - Security-sensitive code requires careful validation
-   **Coverage Impact:** Adds security module coverage

#### test_file_touch.py (Rank #4)

-   **Business Value:** Core file management feature used in multiple tools
-   **Current Coverage:** No equivalent in 859-test baseline
-   **Modernization:** Simple - direct import path update
-   **Test Quality:** Tests timestamp modification, edge cases
-   **Risk:** LOW - Standalone module with minimal dependencies
-   **Coverage Impact:** Fills gap in metadata/file management

#### test_encryption.py (Rank #5)

-   **Business Value:** AES-256-GCM encryption crucial for enterprise security
-   **Current Coverage:** HP-01 validated but detailed encryption logic needed
-   **Modernization:** Medium - requires crypto library validation
-   **Test Quality:** Encryption/decryption cycle, key management tests
-   **Risk:** MEDIUM - Cryptography requires precise implementation
-   **Coverage Impact:** Expands security coverage significantly
