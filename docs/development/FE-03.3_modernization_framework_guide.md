## Overview

The FE-03.3 Modernization Framework extends the FR-01 foundation to provide comprehensive test file modernization capabilities. It automates the transformation of legacy unittest patterns to modern pytest idioms.

## Framework Location

```
scripts/test_modernization/
├── modernization_framework.py    # FE-03.3 Enhanced framework (NEW)
├── import_modernization_script.py  # FR-01.3 Import modernization
├── batch_processor.py             # FR-01.6 Batch processing
└── validation_pipeline.py         # FR-01.7 Validation pipeline
```

## Core Components

### 1. ModernizationFramework Class

The main orchestrator for test modernization.

```python
from scripts.test_modernization.modernization_framework import ModernizationFramework

# Initialize
framework = ModernizationFramework(
    project_root=".",
    custom_rules=[],  # Optional custom rules
    dry_run=True      # Safe mode by default
)

# Analyze a file
result = framework.modernize_file(Path("tests/unit/test_example.py"))

# Check results
print(f"Changes: {result.changes_made}")
print(f"Success: {result.success}")
```

### 2. Modernization Rule Types

| Type          | Description                            | Example                                    |
| ------------- | -------------------------------------- | ------------------------------------------ |
| `IMPORT_PATH` | Updates deprecated import paths        | `file_utilities_2.core` → `src.core`       |
| `ASSERTION`   | Converts unittest assertions to pytest | `self.assertEqual(a, b)` → `assert a == b` |
| `FIXTURE`     | Marks setUp/tearDown for conversion    | Adds TODO comments                         |
| `DECORATOR`   | Updates unittest decorators            | `@unittest.skip` → `@pytest.mark.skip`     |
| `MARKER`      | Adds pytest markers                    | Comment-based markers                      |

### 3. Built-in Rules

#### Import Path Rules (Priority 80-100)

-   `file_utilities_2.core` → `src.core`
-   `file_utilities_1.core` → `src.core`
-   `file_utilities_2.gui` → `src.gui`
-   `empty_folders` → `src.tools.analysis.empty_folders.empty_folders`
-   Size analyzer, checksum, encryption paths

#### Assertion Rules (Priority 70)

-   `self.assertEqual(a, b)` → `assert a == b`
-   `self.assertNotEqual(a, b)` → `assert a != b`
-   `self.assertTrue(x)` → `assert x`
-   `self.assertFalse(x)` → `assert not x`
-   `self.assertIsNone(x)` → `assert x is None`
-   `self.assertIsNotNone(x)` → `assert x is not None`
-   `self.assertIn(a, b)` → `assert a in b`
-   `self.assertNotIn(a, b)` → `assert a not in b`
-   `self.assertIs(a, b)` → `assert a is b`
-   `self.assertIsNot(a, b)` → `assert a is not b`
-   `self.assertGreater(a, b)` → `assert a > b`
-   `self.assertGreaterEqual(a, b)` → `assert a >= b`
-   `self.assertLess(a, b)` → `assert a < b`
-   `self.assertLessEqual(a, b)` → `assert a <= b`
-   `self.assertRaises(E)` context → `pytest.raises(E)`

#### Decorator Rules (Priority 65)

-   `@unittest.skip(reason)` → `@pytest.mark.skip(reason=reason)`
-   `@unittest.skipIf(cond, reason)` → `@pytest.mark.skipif(cond, reason=reason)`
-   `@unittest.skipUnless(cond, reason)` → `@pytest.mark.skipif(not cond, reason=reason)`
-   `@unittest.expectedFailure` → `@pytest.mark.xfail`

## Usage Examples

### Analyze Files (Safe Mode)

```bash
python scripts/test_modernization/modernization_framework.py \
    --analyze-only \
    tests/unit/test_example.py
```

### Generate Analysis Report

```bash
python scripts/test_modernization/modernization_framework.py \
    --analyze-only \
    --report reports/analysis.json \
    tests/
```

### Execute Modernization (Live Mode)

```bash
python scripts/test_modernization/modernization_framework.py \
    --execute \
    tests/unit/test_example.py
```

## Integration with FR-01 Pipeline

The FE-03.3 framework integrates with the existing FR-01 validation pipeline:

```python
# 1. Analyze with FE-03.3 framework
from scripts.test_modernization.modernization_framework import ModernizationFramework
from scripts.test_modernization.validation_pipeline import ValidationPipeline

framework = ModernizationFramework(project_root, dry_run=True)
analysis = framework.analyze_file(test_file)

# 2. If changes needed, use FR-01.7 validation pipeline
if analysis["potential_changes"] > 0:
    pipeline = ValidationPipeline(project_root, rollback_on_failure=True)
    result = pipeline.validate_single(test_file)
```

## Custom Rules

Add custom modernization rules:

```python
from modernization_framework import ModernizationRule, ModernizationType

custom_rule = ModernizationRule(
    name="custom_import",
    type=ModernizationType.IMPORT_PATH,
    pattern=r"from\s+old_module\s+import",
    replacement="from new_module import",
    priority=85,
    description="Update old_module to new_module"
)

framework = ModernizationFramework(
    project_root=".",
    custom_rules=[custom_rule]
)
```

## FixtureMigrator Class

For complex setUp/tearDown migrations:

```python
from modernization_framework import FixtureMigrator

migrator = FixtureMigrator()

# Analyze a test class for fixture opportunities
analysis = migrator.analyze_class(class_content)
print(f"Has setUp: {analysis['has_setUp']}")
print(f"Suggested fixtures: {analysis['suggested_fixtures']}")

# Generate fixture code from setUp/tearDown
fixture_code = migrator.generate_fixture_from_setup(
    setup_code="self.temp_dir = tempfile.mkdtemp()",
    teardown_code="shutil.rmtree(self.temp_dir)",
    fixture_name="temp_test_dir"
)
```

## Validation Workflow

1. **Analyze** - Use `--analyze-only` to preview changes
2. **Review** - Check the generated report for accuracy
3. **Execute** - Run with `--execute` to apply changes
4. **Validate** - Use FR-01.7 pipeline to verify tests pass
5. **Rollback** - Automatic rollback if tests fail

## Known Limitations

1. **Fixture Migration**: Automatic setUp/tearDown conversion is disabled as it requires semantic understanding
2. **Multi-line Assertions**: Complex assertions spanning multiple lines may not be detected
3. **Class Inheritance**: Tests inheriting from custom base classes need manual review
4. **Mocking Patterns**: Mock/patch patterns require manual verification

## Best Practices

1. Always run in `--analyze-only` mode first
2. Review generated reports before executing
3. Use the validation pipeline for automatic rollback
4. Test one file at a time initially
5. Commit changes after each successful modernization batch
