## Relationships & State Transitions

- `UserAccount.preferences_id → PreferenceProfile.preferences_id` (1:1 once activated). Pending accounts delay profile creation until approval.
- `SessionToken.user_id → UserAccount.username`; cascade revoke when `UserAccount.account_status` becomes `blocked` or `disabled`. All DB lookups use the hashed `session_handle_hash`, keeping raw secrets outside persistent storage.
- `ResetRequest.user_id → UserAccount.username`; on completion, forces password change and invalidates all `SessionToken` rows for user.
- `AdminActionAudit.target_username → UserAccount.username` (nullable for global actions).
- `PendingPreferenceAlert.user_id → UserAccount.username`; auto-closes after preferences repaired.

## Lifecycle Notes

1. **Self-Registration**: Creates `UserAccount` with `account_status=pending`, `registration_channel ∈ {hub, cli}`, and serialized `registration_metadata`; no `preferences_id` exists until approval. Approval flow sets status to `active`, stamps `activated_at`, and spawns initial `PreferenceProfile`.
2. **Failed Login**: Increments `login_attempts` and logs to `AdminActionAudit`. On 5th failure flip `account_status=blocked`, create `blocked_at`, and enqueue notification task. For always-available accounts, set `auto_unblock_at` to current time + 15 minutes instead of permanent blocking.
3. **Password Reset**: Creates `ResetRequest`, stores hashed temporary secret, emits audit log. Completion resets `login_attempts`, updates `password_hash`, invalidates sessions, and updates `AdminActionAudit`.
4. **Preference Corruption**: Creates `PendingPreferenceAlert`, new default `PreferenceProfile`, and optional admin notification.
5. **Break-Glass Login**: Creates `BreakGlassUsageLog` entry, marks `SessionToken` with `session_type='break_glass'`, sends `AdminNotification` to all administrators, and requires justification before proceeding.
6. **Break-Glass Logout**: Updates `BreakGlassUsageLog` with `logout_timestamp` and `actions_performed`, triggers immediate password rotation via `ResetRequest`, and marks `post_usage_rotation_status` accordingly.
7. **Always-Available Cooldown**: When an always-available account is blocked, `AlwaysAvailableAccountConfig.last_cooldown_start` is set. After `cooldown_duration_minutes` expires, background watchdog clears `account_status=blocked` and resets `login_attempts`.
8. **Role Migration**: Existing `standard` role accounts are migrated to `user` role. Four roles now exist: `dev`, `admin`, `user`, `readonly`.

These granular entities enable implementation to be decomposed into the "many smaller tasks" mandate: each model/table plus associated service logic can be built and tested independently without blocking the rest of the feature.
